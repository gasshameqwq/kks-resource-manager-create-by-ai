## 1. 一句话总结

**Phase 1 知道「我有什么」，Phase 2 知道「文件内容一样不一样」，
但系统还不会「帮用户整理和标注」。**

所以 Phase 3 要解决的核心不是「再加一个搜索」，而是
**让用户能组织、标注、确认、修正资源**（标签、收藏、备注、归类）。

---

## 2. 现在到底有什么

| 阶段 | 做到了什么 | 通俗说法 |
| :--- | :--- | :--- |
| Phase 1 | 扫描文件、解析卡片、入库、浏览 | 能看、能搜、能筛 |
| Phase 2 | 给文件算内容指纹（sha256）+ 找出「字节完全一样」的文件 | 能判断两份文件是不是同一份拷贝 |

实测：测试全过（734 项），数据库结构没变（还是 v2）。

---

## 3. 现在缺什么（按重要程度）

1. **不能整理**：标签、收藏、集合这些功能**一个都没有**（表建了，但没人用）。
2. **不能人工修正**：想改名字、写备注、纠正类型——没有入口。
3. **没有"用户写入"这套机制**：以前只写扫描结果，从没写过用户自己的数据。
4. **关系很单一**：只知道「这张卡用了哪些 MOD」，其它关系基本没有。

---

## 4. 五个关键问题，一句话回答

| 问题 | 回答 |
| :--- | :--- |
| **怎么认一个文件？** | 靠**路径**。文件一改名或移动，就被当成新资源。 |
| **怎么算"内容一样"？** | 靠 **sha256**，只证明**字节完全一样**，不代表同一个角色。 |
| **能证明"MOD 依赖 MOD"吗？** | **不能。** 数据里根本没有依赖信息，只有"卡片用了哪个 MOD"。 |
| **能找到"同一个角色"吗？** | **不能自动做到。** 样本里确实存在，但算不出来，只能做成"候选 + 人工确认"。 |
| **整理会动文件吗？** | **不会。** 整理只写数据库，不移动、不改名、不删除任何文件。 |

---

## 5. 身份与相似性的通俗分级

- **能当事实（可靠）**：两份文件字节完全一样；两个 zipmod 是同一个 MOD（GUID 相同）。
- **只能当候选（要人确认）**：文件大小一样、名字一样——**都有反例，不能当证据**。
- **目前做不到**：同角色、版本、变体、看起来像、意思像。

> 原则：**没有数据来源的关系，宁可先不做。**

---

## 6. 外部项目怎么看

- **KKManager（同类工具）**：能看已装 MOD、能**联网自动更新**、能**删重复文件**。
- 但它这些能力和我们三条底线**冲突**：
  - 本地优先（不联网）
  - 默认只读（不动、不删文件）
  - 位置与分类分离
- 结论：可以学它的**概念**（用 GUID 认 MOD、候选重复要人确认），
  **不能照搬它的行为**（下载、安装、删除）。
